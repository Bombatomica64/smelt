# TypeScript Frontend (`smelt-frontend-ts`)

The TS frontend turns a `.ts` source file into a `smelt_hir::Module`. It enforces the supported subset, runs external tools (oxclint, tsgo), and produces source-located errors for everything it rejects.

## Inputs and Outputs

```
fn check(path: &Path) -> Result<(), Vec<SmeltError>>
fn to_hir(source: &str, file_id: FileId, ctx: &mut HirCtx) -> Result<ModuleId, Vec<SmeltError>>
```

`HirCtx` owns the `Crate` arenas (types, symbols, bodies). Multiple files share one `HirCtx`.

## Pipeline (per the check-pipeline spec)

```
.ts source
   │
   ▼
1. oxclint            — fast lint pass; rejects style + forbidden patterns
   │
   ▼
2. tsgo --noEmit      — type-check; populates an annotated AST
   │
   ▼
3. smelt rules        — reject AST shapes that have no HIR representation
   │
   ▼
4. HIR construction   — walk the typed AST, produce smelt_hir::Module
```

Each phase runs only if the previous one succeeded. Phase 3 assumes a fully type-checked AST; phase 4 assumes phase 3 has filtered out unsupported shapes.

### Phase 1: oxclint

Run via subprocess. Exit code != 0 → collect oxclint's JSON output, convert each diagnostic to `SmeltError` with the original span, fail.

oxclint config (`.oxlintrc.json`, generated by `smelt new`):

- `no-explicit-any`: error
- `no-var`: error
- `no-eval`: error
- `no-with`: error
- (extend as smelt rules grow)

### Phase 2: tsgo --noEmit

Run via subprocess. tsgo is the Go-port TypeScript compiler (TS 7+). If not on `$PATH` or in `node_modules/.bin`, fail with a clear install instructions message — **do not fall back to `tsc`**. Both tsgo and smelt are alpha and stabilize together.

Type errors → `SmeltError` per diagnostic with the source span.

### Phase 3: smelt rules

A separate visitor pass over the oxc `Program` (already type-annotated by phase 2). Each rule is its own function, registered in a `rules` registry. Each produces zero or more `SmeltError`s.

| Rule code                             | Rejects                                                    |
|---------------------------------------|------------------------------------------------------------|
| `smelt::no-any`                       | `any` in any annotation, signature, or cast                |
| `smelt::no-unknown`                   | `unknown` (use a discriminated union instead)              |
| `smelt::no-never`                     | `never` (no HIR representation)                            |
| `smelt::no-conditional-types`         | `T extends U ? X : Y`                                      |
| `smelt::no-mapped-types`              | `{ [K in T]: U }`                                          |
| `smelt::no-template-literal-types`    | `` `prefix-${T}` ``                                        |
| `smelt::no-index-signatures`          | `{ [k: string]: T }`                                       |
| `smelt::no-eval`                      | `eval`, `new Function(...)`, `with`                        |
| `smelt::no-decorators`                | decorator syntax (deferred to v1.1)                        |
| `smelt::no-var`                       | `var` (use `let`/`const`)                                  |
| `smelt::no-jsx`                       | JSX/TSX syntax                                             |
| `smelt::no-namespace`                 | `namespace`/`module` declarations                          |
| `smelt::no-mixed-eq`                  | `==` between mixed-type operands (use `===` on same types) |
| `smelt::no-untyped-let`               | `let x = …` where the inferred type contains `any`         |
| `smelt::no-multiple-inheritance`      | `class C extends A, B` (the parser would reject; safety)   |

Each rule's error includes the file and span and a one-line `why-this-is-rejected` message.

### Phase 4: HIR construction

A visitor that walks the typed oxc AST and produces `smelt_hir::Module` via `HirCtx`. The walker assumes:

- The AST has been type-checked (phase 2). Every expression has a resolved oxc type.
- The AST has been screened (phase 3). Every shape it sees is convertible.

Construction patterns:

- **Identifier rename:** every `camelCase` identifier becomes `snake_case` via a deterministic converter. Original spelling stored in `OriginalNameTable`.
- **Type translation:** oxc types map onto `smelt_hir::Type` via a thin `oxc_ty_to_hir(ty: &oxc::TypeId) -> TypeId` helper. `number` → `Float`. `bigint` → not supported (extend rules to reject it).
- **Bodies:** each function/method opens a fresh `Body`, allocates `LocalId`s for its parameters, recurses on the body block.
- **Expressions:** every visit returns `(ExprId, TypeId, Span)`. Expressions are inserted into the current `Body::exprs` arena.
- **Closures:** arrow functions and function expressions become `ExprKind::Lambda` with their own nested `Body` recorded as the lambda's body.
- **Classes:** field declarations become `Field`s, methods become separate `FunctionId`s linked from `Class::methods`. Constructors become a method named `__init__` (canonical HIR convention).
- **Imports:** each `import { x } from './y'` becomes one `Import` per imported name. Path is resolved relative to manifest sources/roots; resolution and cross-file linking happens in the CLI driver, not here.

## Naming Normalization

```rust
fn camel_to_snake(name: &str) -> Symbol
```

- `myFunction` → `my_function`
- `URLParser` → `url_parser`
- `_internal` → `_internal` (leading underscore preserved)
- Class names: `MyClass` → kept as `MyClass` (PascalCase, matching Rust)

The original spelling is recorded in `OriginalNameTable`. Diagnostics use original names; emitted Rust uses canonical.

## Type Mapping

| TS type                | HIR type                                  | Notes                              |
|------------------------|-------------------------------------------|------------------------------------|
| `number`               | `Type::Float`                             | TS has no int/float split          |
| `bigint`               | (rejected)                                | smelt rule                         |
| `string`               | `Type::String`                            |                                    |
| `boolean`              | `Type::Bool`                              |                                    |
| `null` / `undefined`   | `Type::None`                              | unified                            |
| `void`                 | `Type::None`                              | function-return position           |
| `T[]` / `Array<T>`     | `Type::List(T)`                           |                                    |
| `[T, U]`               | `Type::Tuple([T, U])`                     |                                    |
| `Record<K, V>`         | `Type::Dict(K, V)`                        | only when K is `string` or `number`|
| `T \| null` / `T \| undefined` | `Type::Optional(T)`               |                                    |
| Discriminated union    | `Type::Union(variants)`                   | requires literal tag field         |
| `interface I { … }`    | `Type::Class(synthesized_id)`             | interfaces lower to structural classes |
| `class C { … }`        | `Type::Class(C)`                          |                                    |
| `Promise<T>`           | `Type::Future(T)`                         |                                    |

## Errors

Every error is a `SmeltError`:

```rust
pub struct SmeltError {
    pub code:    &'static str,    // "smelt::no-any"
    pub span:    Span,            // (FileId, ByteRange)
    pub message: String,
    pub note:    Option<String>,  // optional follow-up explanation
}
```

Phases collect errors into a `Vec<SmeltError>`; the CLI prints them in source order.

## Current Gaps

- `lib.rs::to_hir` is a stub that creates a parser but never produces HIR.
- `checker.rs` shells to `tsc` and `oxlint` via `npx`. Spec mandates `tsgo` and `oxclint`.
- `examples/parser.rs` is a useful exploration of `oxc`'s semantic API; mine it for the HIR walker.
- No `SmeltError` type yet; everything is `Box<dyn Error>` and loses spans.
- No smelt rules implemented.
- No naming normalizer.
- No oxc-type → HIR-type translator.
