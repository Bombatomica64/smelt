1. The pipeline

One driver, ManifestLowering, serves build, check, probe, the dumps and every report. The labels on the arrows are the Rust values handed over. Type facts enter in two places: the type gate runs tsrs and ty over every source before anything lowers, and the frontends read the facts back by span (FrontendOptions::ts_facts) or through ty_resolve. The frontend decides almost every erasure; MIR and codegen inherit them (section 4).

Features cut the graph at three dashed edges: smelt-transpiler's defaults are ty and ts7, so --no-default-features drops smelt-frontend-py, smelt-py-types and smelt-ts-types (tsrs) from the CLI, and TypeScript then lowers from annotations alone (ts_facts.rs). smelt-codegen-rust takes smelt-runtime with default-features = false: the text, not the compiled runtime. default-members leaves out smelt-ts-types, smelt-ts-model and smelt-py-types.

4. The life of one value's type

A type is decided once, in the frontend, and carried by TypeId through HIR and MIR (MIR clones HIR's interner) to FunctionEmitter::rust_type. The trace above is a golden example: Config['tags'] is a type-level form the frontend does not evaluate, so it erases with type-level; tsrs answers the span with string[], the record is dropped and the value stays SmeltList<JsString>. The bars are erasure records per reason from the committed baselines (es-toolkit 2026-11-14, remeda 2026-11-08): es-toolkit 4,444 records, 3,813 avoidable, 3,432 decided by the frontend and 1,012 by codegen; remeda 3,771, 2,886 avoidable, 2,294 frontend and 1,477 codegen. The largest avoidable causes are explicit-any in es-toolkit (1,180: the source opts out), then erased-generic (687 / 779: a type parameter no Rust generic carries), type-level, missing-annotation and erased-union. "Code mentions" counts ErasureReason::X in non-test frontend code, a proxy for decision sites. MIR's two retypings to Unknown record no reason, so the sidecar cannot attribute them.

5. MIR in one picture

MIR is a CFG over mutable, typed locals (not SSA). Only Call and Await carry an unwind edge, so anything that can throw is one of them; a function whose throw escapes gets can_throw and codegen returns a Result. Order read from compile.rs, lower/mod.rs (lower_hir, run_finalization_passes) and opt/mod.rs (fixpoint_passes, try_optimize).

8. Heat map

733 non-merge commits since 2026-09-15. A module is a file plus its directory, one level deeper inside lowering/, emitter/, runtime/, lower/ and opt/; test directories are left out. Ringed: the three to look at first.

  1. frontend-ts lowering/stdlib: 25,617 lines, 130 commits, 48,258 lines changed. The largest and hottest module; call_dispatch.rs alone took 66 commits. Every host API is recognised here, and it holds the most untyped-builtin, external-type and unmodeled-type erase sites, so it is where per-API special cases would accumulate and where typed host models pay off first.
  2. codegen emitter/coercion: 8,320 lines, 91 commits. The one typed ↔ SmeltUnknown seam; function_adapter.rs is the 7th largest file. Churn here follows erasure upstream: each new erased shape needs an adapter, so it should cool as section 4's avoidable counts fall. A rise is an early signal of erasure leaking.
  3. frontend-ts lowering/expr: 10,986 lines, 88 commits; references.rs (3rd largest file) and member_access.rs. It holds the most by-name and dynamic-operator sites, the two frontend reasons with the most code mentions after missing-annotation.

Moves inside the window: emitter/core.rs and emitter/call_runtime.rs were split by concern on 2026-11-07, and the *_prelude.rs runtime strings left smelt-codegen-rust for smelt-runtime; their history shows as churn on files that are now small or gone (gone ones are not plotted).
