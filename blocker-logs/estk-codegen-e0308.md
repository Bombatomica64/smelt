# es-toolkit codegen — systematic E0308 (mismatched types) fixes

Target: drive down `E0308 "mismatched types"` in the whole-crate transpile of
es-toolkit (`<es-toolkit>/dist-smelt`, pinned ref `e008a2818cd8`).

## Result

Measured with `smelt rust-diagnostics` on `dist-smelt` regenerated by the branch
binary:

| Metric | Before | After |
| --- | --- | --- |
| E0308 diagnostics | 394 | 185 |
| Total errors | 525 | 320 |

E0308 clustering confirmed the hypothesis: a small number of general emitter
bugs fired across many generated sites. Four systematic root causes were found
and fixed generally in `crates/smelt-codegen-rust`.

## Root causes fixed

1. **Iterable-to-list extraction matched `SmeltUnknown::` arms on a non-erased
   source** (`emitter/coercion.rs`, `extract_value_text`, the three `Type::List`
   arms). The list-extraction template emitted
   `let smelt_src = {text}.clone(); … match smelt_src { SmeltUnknown::Array(..) => .. }`,
   assuming the source expression is already an erased `SmeltUnknown`. When the
   source is statically typed — e.g. `Array.from(arr)` where
   `arr: ArrayLike<T> | null | undefined` lowers to `Option<SmeltList<SmeltUnknown>>`
   — the `SmeltUnknown::` patterns do not type-check against the `Option`/`SmeltList`
   value. Fix: normalize the source through the `IntoSmeltUnknown` boundary
   adapter first (`({text}).clone().into_smelt_unknown()`), exactly as the
   sibling `Type::Dict` arms already do. Identity on an existing `SmeltUnknown`;
   preserves the backing array id. **Largest cluster (~185 sites, e.g.
   compact/difference/intersection/uniq/without/flatten/join…).**

2. **Fallible (`may_throw`) array predicate result used in boolean position
   without unwrapping** (`emitter/list_query.rs`, predicate emitter for
   `find`/`findLast`/`findIndex`/`findLastIndex`/`some`/`every`/`filter`). A
   throwing callback is emitted as a closure returning
   `Result<_, Box<dyn Error>>`, but the call site consumed it directly in
   `if …`/`.any`/`.all`, yielding `expected bool, found Result<bool, _>`. Fix:
   unwrap the `Result` with the same `.unwrap_or_else(|error| panic!(..))`
   `list_map_closure_text` already uses, before applying truthiness.
   (findIndex/findLastIndex/takeWhile/takeRightWhile.)

3. **Whole-parameter rebind promoted to the shared `&mut` ABI**
   (`emitter/core.rs`, `parameter_needs_mutable_reference_in_seen`). The match
   arm lumped `AssignPlace { place: Place::Local(param) }` (a *rebind* of the
   whole parameter, `iteratees = iteratees[0]`) together with `Place::Field` /
   `Place::Index` (in-place mutation). A rebind is a local reassignment that
   JavaScript never propagates to the caller, so it must stay an owned `mut`
   binding — as the function's own docstring already states. The `&mut` type
   then rejected an owned assignment. Fix: only `Place::Field` / `Place::Index`
   in-place mutation triggers the reference ABI. (over/sortBy/xorBy/xorWith/
   omit/invoke.)

4. **Rebound callback parameter left as borrowed `&dyn Fn`**
   (`emitter/mod.rs`, `callback_param_escapes_locally`). A callback parameter
   that is rebound in the body (`callback = <owned Rc<dyn Fn>>`, e.g. the
   `mapAsync`/`filterAsync`/`flatMapAsync`/`forEachAsync` concurrency wrappers
   reassign the callback to a `limitAsync`-wrapped handle) receives an owned
   `Rc<dyn Fn…>` that a borrowed `&dyn Fn` binding cannot hold. Fix: treat a
   local rebind as a reason the parameter must enter the function as an owned
   handle.

Each fix has a codegen regression test in `crates/smelt-codegen-rust/src/tests/part_1_tests.rs`:
`erases_optional_list_source_before_iterable_extraction`,
`unwraps_fallible_predicate_result_in_list_query`,
`keeps_rebound_list_parameter_owned`,
`keeps_rebound_callback_parameter_owned`.

## Deferred (genuinely hard / single-site)

- **`loop`-as-expression not carrying its break value** (~17 "found `()`" +
  related "expected `()`" sites: cond/flatten/rest/rearg/overArgs/overEvery/
  overSome/bind/bindKey/attemptAsync/template/orderBy). A value that should be
  `break value;` from a value-producing `loop` is emitted as `value; break;`,
  so the loop yields `()`. This needs CFG-lowering work in
  `emitter/control_flow.rs` that risks regressing the many passing loop tests,
  and overlaps return/throw semantics owned by the sibling error-class lane.
- **`Option<ConcreteUnion>` truthiness** (truncate.rs, 18 errors from one match
  site): the optional-truthiness match emits `Some(SmeltUnknown::…)` arms
  against an `Option<SmeltUnion…>`; the concrete-union inner needs erasing to
  `SmeltUnknown` first. Single fan-out site; left for a union-boundary pass.
- Remaining are concentrated single-file cases (template.rs, orderBy.rs,
  clone_1.rs, camelCase_1.rs, zipObjectDeep.rs) and small generic-instantiation
  / async `Result`-wrapping mismatches — closer to per-function specifics than
  broad emitter bugs.
